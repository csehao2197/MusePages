# MusePages

**A collection of website front pages generated from prompts.**

MusePages 收集由 AI 根据原始需求生成的网站首页。同一个 prompt 可以交给不同模型，生成代码彼此隔离，最终将可独立访问的静态首页汇入同一个作品集，通过 Cloudflare 托管。

**当前仅允许修改 Markdown 文档，不运行生成、构建或发布，不改写代码、配置、网站产物和日志。当前更新markdown文档是对项目经行设计 不需要关系项目现有状况** 下文的使用说明供获准执行时参考；“待实现方案”不是现有功能。

## 目标网站设计

### 目标网站结构

目标网站是 AI 生成的网页首页作品集，按 prompt 组织作品，方便用户浏览并比较不同模型对同一需求的生成效果。

集合首页以响应式网格排列作品面板（panel）。每个 prompt 对应一个面板，同一 prompt 的不同模型结果在面板内通过轮播（Carousel）展示，不重复创建面板。

每个面板包含以下内容：

- **作品名称**：使用易读的标题，不展示 prompt 的内部编号。
- **首页预览**：每张 slide 展示一个模型生成的首页截图，并标注真实模型名称和风格标签。
- **轮播控件**：每个参与发布的模型结果对应一个圆点，按发布配置排序；支持圆点选择、前后切换、键盘操作和移动端滑动。切换时，预览、模型信息与访问链接同步更新。
- **访问入口**：提供作品详情页、当前模型生成页面及“Read prompt”入口。原始需求在只读文字展示页中呈现，不直接下载 Markdown。

只有一个模型时保留一个圆点，隐藏或禁用前后按钮；没有选中模型时不展示该作品面板。作品详情页同样支持模型轮播，各模型首页保留独立访问地址。截图仅用于预览，不能替代可访问的网页。

目标网站的具体布局、视觉风格和交互细节以 `deploy\MusePages\README.md` 为设计标准。

## 工作流

### 页面生成工作流

页面生成工作流以用户指定的 `<ai model>` 为输入，读取根目录 `config.json` 中的模型服务配置，由 `src\workflows\render-prompt-pages.mjs` 遍历原始 prompt，按需生成该模型对应的网站代码与静态首页。

流程依次完成模型配置校验、已有结果检查、缺失页面生成、静态产物准备和发布选项登记，不自动部署目标网站。脚本的目录结构、执行步骤和状态处理见[源码结构与说明](#源码结构与说明)。

### AI页面生成工作流

AI 页面生成工作流以用户指定的 `<ai model>` 为输入，由 AI agent 读取 `src\workflows\render-prompt-pages.md`，按照其中的指引组织执行页面生成任务。它与页面生成工作流的目标一致，区别在于由 agent 根据 Markdown 指令编排，而非由 `.mjs` 脚本编排。

Agent 应遵循[页面生成脚本](#页面生成脚本)相同的模型配置、原始需求、设计指引和结果检查规则，将源码保存到 `out\pages\<prompt>\<ai model>\`，静态首页及资源保存到其 `out\` 子目录，并如实更新元数据、登记默认关闭的发布选项。编排 agent 的模型身份不能代替实际生成页面的模型身份。

执行前检查已有结果，有效结果跳过；需要覆盖或重新生成时先取得确认。失败或中断时保留已有代码与真实状态，恢复时只补未完成的步骤。结束后报告生成、跳过、待确认和失败项，不自动部署目标网站。

### deploy工作流

deploy 工作流以 `deploy\config.json` 中的发布选择为输入，由 `src\workflows\deploy-site.mjs` 组装本地目标网站，输出到 `deploy\MusePages\`，作为 Cloudflare 的静态发布根目录。

流程只汇集已启用的 prompt／模型结果，从 `out\pages\<prompt>\<ai model>\out\` 读取准备好的静态首页及必要资源，不复制项目源码或内部配置。集合首页、作品详情页、模型轮播及 prompt 文字展示按[目标网站结构](#目标网站结构)组织；模型顺序沿用发布配置，公开路径移除 prompt 编号。

执行前逐项读取 `out\pages\<prompt>\<ai model>\metadata.json`，核对生成、静态验证和发布状态，并检查实际静态产物及目标网站中的对应页面，按以下规则处理：

1. **已完成发布**：当前版本的静态首页及资源有效，目标页面完整且版本一致时，跳过重复部署；元数据状态未同步的，仅核验后补写状态，不能只凭 `deployed: true` 判断完成。
2. **待部署**：静态产物有效，但目标页面缺失、不完整或版本过旧时，纠正过时的发布标记，将该结果列入本次待部署清单，不重新生成或构建源码。
3. **异常**：必需元数据缺失、模型归属或路径冲突、静态产物缺失或验证失败时，记录对应 prompt、模型及原因，中止本次发布并保留旧站，不静默跳过选中项或标记成功。

对待部署结果在临时目录准备候选文件，按[发布安全](#发布安全)完成验证、切换和目标核验后，再更新对应发布状态。已发布结果即使跳过重复部署，仍须参与集合首页、详情页和轮播的汇总，按当前配置同步模型顺序、展示信息及访问链接。

该工作流不调用 AI、不重新生成或构建作品源码，也不直接上传 Cloudflare。结束后报告本次部署、已部署跳过、状态补写及异常清单；本地汇集成功不代表已完成线上部署。

## 源码结构与说明

页面生成脚本的输入、执行入口和输出按以下结构组织：

```text
config.json                         # 模型服务配置
DESIGN.md                           # 通用设计指引
data\
  prompts\                          # 原始 Markdown 需求
src\
  workflows\
    render-prompt-pages.mjs          # 页面生成编排入口
    render-prompt-pages.md           # 页面生成编排入口Prompt
out\
  pages\
    <prompt>\
      <ai model>\
        metadata.json               # 模型身份、生成与验证等状态
        ...                         # 生成的网站源码
        out\
          index.html                # 用于发布的静态首页
          ...                       # 静态资源
deploy\
  config.json                       # 模型结果的发布选择
```

`<prompt>` 是原始 Markdown 文件名去除 `.md` 后的名称，保留内部编号；`<ai model>` 是模型对应的稳定目录名，真实模型 ID 记录在元数据中。不同 prompt、不同模型的源码与静态产物互不覆盖。

### 页面生成脚本

`src\workflows\render-prompt-pages.mjs` 负责遍历需求、调用指定模型、检查生成结果并登记发布选项，按以下顺序执行：

1. **校验模型配置**：根据输入的模型名称读取根目录 `config.json`，取得调用 URI、接口类型与实际模型 ID，验证连接及模型身份。配置名称不能代替真实模型标识；认证信息仅从本地环境读取。
2. **读取需求与设计指引**：遍历 `data\prompts\` 中各项目的原始 Markdown，结合根目录 `DESIGN.md` 准备生成输入，不修改原始需求。
3. **判断是否需要生成**：对照 `metadata.json`、实际代码和当前需求判断完成情况。有效结果跳过；已有代码但记录不可信、生成不完整或输入已变化的，列为待确认或获准重试项，不直接覆盖。仅缺少静态导出时，保留源码，只补后续静态产物。
4. **调用 Codex 生成源码**：对获准生成的缺失项，再次检查结果并加锁，以对应模型目录为子进程工作目录调用 `codex exec`。通过 `-c` 配置模型服务连接、通过 `--model` 选择实际模型；原始 prompt、设计指引和输出要求通过位置参数或标准输入传入，不把 `-c` 当作提示词参数。
5. **准备并检查静态首页**：源码保存在模型目录，用于发布的首页及资源放在其 `out\` 子目录。页面须可独立静态运行，资源引用适用于最终发布子路径；不能用项目源码、`.next` 或截图代替静态首页。
6. **更新记录与发布选项**：核验实际结果后更新元数据，将该 prompt／模型组合登记到 `deploy\config.json`。新选项默认关闭，已有选项不重复添加、不改变开关；登记失败时保留生成代码，下次仅补登记。

### 页面生成Markdown
`src\workflows\render-prompt-pages.md`

### 结果记录与恢复

`out\pages\<prompt>\<ai model>\metadata.json` 保存当前模型结果的身份、静态产物位置及执行状态。生成、配置登记、静态验证和部署分别记录，不能因为目录存在、Codex 退出成功或配置已登记就将全部阶段标为完成。

脚本应设置超时和有限重试，失败时保留原因与已有有效结果；中断后依据元数据和实际文件继续处理。结束时输出生成、跳过、待确认和失败列表，部署由独立工作流执行。

## 使用现有工具

所有命令从仓库根目录执行。优先复用已有依赖；缺少依赖时先运行 `npm install`。示例截图需要可用的 Playwright Chromium。

### 生成示例与登记结果

```powershell
# 生成固定示例及截图，自动登记发布选项，不改当前网站
npm run generate:sample

# 扫描已有输出，补充发布选项
npm run deploy:sync

# 可选：持续监听外部生成的新结果，按 Ctrl+C 停止
npm run deploy:watch
```

固定示例写入 `out/pages/001-destination-guide/unspecified/`。`unspecified` 表示模型未知，不能改名冒充某个已知模型。

每次生成代码后，生成流程应调用 `syncDeployConfig` 或 `npm run deploy:sync`；现有示例已接入。同步只登记含 HTML `index.html` 或声明 Next.js 依赖的 `package.json` 的目录，新选项默认关闭，已有组合不重复添加、不改变开关。登记不等于验证或发布成功。

### 选择发布内容

编辑 [deploy/config.json](./deploy/config.json)。**当前脚本仅支持 version 1**，每个数组项对应一个 prompt／模型组合：

```json
{
  "version": 1,
  "pages": [
    {
      "prompt": "006-travel-agency-homepage",
      "model": "model-a",
      "enabled": true,
      "slug": "travel-agency-homepage",
      "title": "旅行社首页",
      "tags": ["Travel"],
      "staticDir": "."
    }
  ]
}
```

这是格式示例，不保证对应结果已存在。`prompt` 对应原始 Markdown 文件名（不含扩展名），`model` 对应模型目录，`enabled` 控制是否发布。`staticDir` 相对于模型目录：HTML 通常为 `"."`，Next.js 通常为已准备好的 `"out"` 静态导出目录。

### 重建本地网站

确认所选结果的静态首页与资源有效后，运行：

```powershell
npm run deploy
```

该命令在发布前再次扫描选项，按配置完整重建 `deploy/MusePages/`，入口为 `index.html`。它不执行 Next.js 构建，也不上传 Cloudflare。

**完整重建会移除未选中的旧页面和卡片。** 历史网站内容不会自动成为源码选项；全部选项关闭时，将生成无作品的有效集合首页。不要仅为试用命令而替换当前网站。选中项无效时，发布中止并保留旧站，详见[发布安全](#发布安全)。

## 内容与路径约定

### 源码与模型身份

`<prompt_file_name>` 必须取自原始 Markdown 文件名，去掉 `.md`，内部编号保留。`<ai_model_name>` 是真实模型对应的稳定目录名，须适合文件系统和 URL，并记录其与实际模型 ID 的映射。

同一 prompt 的不同模型结果互不覆盖。输入文件重名、模型名规范化冲突时，应明确报告并解决，不能静默合并。模型目录保存实际网站代码，不只是截图、需求文件或占位内容；Next.js 源码目录不必直接包含静态 `index.html`。

### 内部编号与公开路径

编号用于来源追踪、状态和日志，不能出现在公开卡片、标题、导航、页面元数据或资源路径中。只移除 prompt 编号前缀，不改变价格、日期等业务数字；去编号后重名时使用稳定的语义后缀。

| 对象 | 示例 |
| --- | --- |
| 原始输入 | `data/prompts/006-travel-agency-homepage/006-travel-agency-homepage.md` |
| 生成代码 | `out/pages/006-travel-agency-homepage/<ai_model_name>/` |
| 模型首页 | `deploy/MusePages/pages/travel-agency-homepage/<ai_model_name>/index.html` |
| 展示名称 | 旅行社首页 |

目标网站将增加 prompt 层的作品详情页，结构如下；该详情页与 Carousel 尚未实现：

```text
deploy/MusePages/
  index.html
  pages/
    travel-agency-homepage/
      index.html                 # 待实现：多模型作品详情
      <ai_model_name>/
        index.html
        prompt.html
        preview.png              # 可选
        ...静态资源
```

### Prompt 文字展示

“Read prompt”链接到静态 `prompt.html`，不直接链接或下载 Markdown。页面以只读 `<pre><code>` 展示经过转义的原文，保留文字与换行，不执行其中的 HTML 或脚本。

展示区应可滚动、可选择复制，适配桌面和移动端，并提供正确的返回集合链接。现有发布流程为选中结果生成此页面。

### 静态产物边界

HTML 结果发布首页及必要的 CSS、浏览器 JavaScript、图片和字体；Next.js 结果先取得有效静态导出，保留所需的 `_next/static/` 等浏览器资源。导出不得覆盖源码，截图不能替代可访问首页。

首页必须脱离 Next.js 服务端、API 路由、数据库和生成时的本地进程运行。必要时在批准范围内静态适配或 Mock 后重新验证；无法导出时记录阻塞，不能改为部署 Next.js 服务。

只发布公开页面、浏览器资源、prompt 展示页及必要许可证，不整体复制源码项目或 `out/pages/`。排除 `package.json`、`app/`、组件源码、`node_modules/`、`.next/`、服务端产物、构建缓存、内部元数据、原始 Markdown、配置、任务文件、报告、日志和凭据。生成与部署脚本不得混入网站，但页面实际使用的浏览器脚本须保留。

所有资源与导航须适用于 `pages/<prompt_slug>/<ai_model_name>/` 子路径，不能依赖开发机绝对路径或假定 `/_next/...` 位于站点根目录。链接显式指向 `index.html`，新增模型层级后重新计算返回路径。提供 `preview.png` 时展示截图，否则明确显示未提供预览。

## 生成与汇集流程

以下是完整目标流程，不表示所有阶段已经自动化。执行前读取 [AGENTS.md](./AGENTS.md)，确认本轮范围与授权。

| 阶段 | 工作与产出 |
| --- | --- |
| 读取需求 | 枚举原始 prompt，不将 README 或生成记录当作输入；读取 `DESIGN.md`，检查已有实现、模型映射与状态 |
| 生成代码 | 按真实模型写入独立源码目录，复用现有依赖，实现首页与必要交互，不擅自扩展范围或用统一占位模板替代设计 |
| 准备静态首页 | 根据项目类型取得首页及资源，保留源码，按静态产物边界处理服务端依赖 |
| 登记并选择 | 同步发布选项，由管理员决定哪些模型公开；选择发布不等于生成或验证完成 |
| 验证并汇集 | 检查候选集合和实际模型子路径，通过后切换网站，按真实结果更新获准维护的状态与报告 |

作品 README 应说明原始 prompt、真实模型、实现类型、源码位置、主要功能、运行与验证命令、静态导出和发布路径、Mock、环境变量及限制。

AI 凭据只在生成环境使用，不写入源码、日志、浏览器或静态产物；不得未经授权向远程 AI 发送敏感或受限内容。

### 发布安全

现有完整发布以配置为准，先检查原始 prompt、选中结果的静态首页，在临时目录组装候选站点，并检查 HTML 中的本地链接和资源。任一选中项缺失、路径非法、冲突或复制失败，整次发布中止，不静默跳过。

候选站点全部通过检查后才替换旧站；切换失败尝试回滚，回滚也失败时保留恢复文件并报告路径。发布配置和既有 `.git` 必须保留，不能递归删除整个 deploy 或嵌套仓库根目录，也不能公开 Git 元数据。

发布使用 `deploy/.publish.lock`。意外中断后，先确认相关进程已退出，再处理过期锁并检查日志及恢复目录，不能盲目重试。完整发布与未来的增量发布应共用检查、锁、切换和恢复机制。

本地发布仅组装静态文件，不处理密钥、不上传 Cloudflare；不再使用 SSH 部署流程。

## 待实现方案

### version 2 发布配置

目标配置按 prompt 聚合模型，仅保存发布选择；展示与导出信息移入 out 元数据：

```json
{
  "version": 2,
  "pages": [
    {
      "prompt": "006-travel-agency-homepage",
      "model": [
        { "name": "model-a", "enabled": true },
        { "name": "model-b", "enabled": false }
      ]
    }
  ]
}
```

每个 `prompt` 只出现一次，`model[].name` 对应模型目录且不能重复，数组顺序决定 Carousel 中已发布模型的顺序。只发布 `enabled: true` 的有效结果；模型数组为空或全部关闭时，不发布该 prompt 的卡片、详情页和模型目录。

同步需保留已有模型顺序和开关，新模型默认 `enabled: false`。重新生成同一组合不重复登记；源码临时缺失也不自动删除旧配置，选中项缺失时应恢复源码或取消选择。

迁移前保留每个组合的开关与顺序，将旧 `slug`、`title`、`tags`、`staticDir` 移入对应元数据，核验后再切换版本。共享字段冲突、已有元数据不一致或输入缺失时停止并报告，不静默覆盖或丢弃旧配置。

### 生成结果元数据

prompt 共享信息保存到 `out/pages/<prompt_file_name>/metadata.json`：

```json
{
  "slug": "travel-agency-homepage",
  "title": "旅行社首页"
}
```

模型信息保存到 `out/pages/<prompt_file_name>/<ai_model_name>/metadata.json`：

```json
{
  "modelId": "actual-model-id",
  "tags": ["Travel"],
  "staticDir": ".",
  "generated": false,
  "config_added": false,
  "validated": false,
  "deployed": false
}
```

`modelId` 记录真实模型，不能用 CLI 名称冒充；`tags` 属于对应模型效果。`staticDir` 相对于模型源码目录，HTML 默认为 `"."`，Next.js 默认为 `"out"`，也可声明实际导出子目录。

| 状态 | 何时成立 |
| --- | --- |
| `generated` | 当前版本代码已实际生成并核验，不以目录存在或 Agent 退出成功为准 |
| `config_added` | 配置已成功保存，且核验对应 prompt／模型项存在；与开关无关 |
| `validated` | 当前版本静态首页及其资源已通过实际验证 |
| `deployed` | 当前版本已成功纳入本地 `deploy/MusePages/` 并核验目标，不代表上传 Cloudflare |

各阶段只维护自身状态；同步负责选项及 `config_added`，管理员切换开关不直接修改执行状态。重新生成后必须重置验证与发布状态，配置项移除后不能保留过时的登记成功标记。

发布按 prompt／模型读取元数据，核对公开路径、模型归属和静态导出。必需字段缺失、非法或冲突时中止并保留旧站，不从旧配置字段兜底或编造值。

元数据文件不进入网站，但允许展示其中可公开的标题、标签与模型信息；排除内部元数据时不能误删网页运行所需的其他 JSON 资源。

### 多模型 Carousel

一个 prompt 对应一张集合卡片和一个详情页 `pages/<prompt_slug>/index.html`。卡片与详情页均通过 Carousel 展示已发布模型，各模型仍链接到独立的 `<ai_model_name>/index.html`，保留 prompt 展示入口。

| 场景 | 展示要求 |
| --- | --- |
| N 个已选择且通过验证的模型 | N 张 slide、N 个圆点，沿用配置顺序，不按全站模型或未发布结果计数 |
| 切换模型 | 静态预览、真实模型名称、标签和访问链接同步更新 |
| 一个模型 | 保留一个圆点，隐藏或禁用前后按钮 |
| 零模型 | 不发布该作品的卡片、详情页或模型目录 |
| 取消某个模型 | 重建 slide、圆点和有效当前项 |
| 选中结果无效 | 中止发布并保留旧站，不静默省略 |

圆点可直接选择模型，支持前后切换、键盘操作和移动端触摸滑动，当前点有明确视觉状态及可访问性标识。使用截图而不是实时 iframe，默认手动切换，不强制自动播放，遵守减少动态效果设置。

集合保留暖白背景、深绿文字与操作、衬线标题和响应式方形卡片；模型作品保留各自的视觉特色。轮播仅用于集合展示，不要求重写生成网站的业务页面。

### 生成覆盖检查与模型匹配

计划在 build 工作流前增加 Node.js 只检查模式，并与补生成共用判断逻辑；它不是 Next.js 编译，现有 `generate:sample`、`deploy:sync` 均不能替代。

1. **确定期望范围**：枚举原始 prompt，与显式目标模型清单组成全部适用组合，不能只从 out 或发布配置推断。发布开关只控制公开，不改变生成覆盖要求。
2. **核验实际结果**：结合完成记录、实际代码和原始 prompt 内容标识判断。HTML 需有实际首页及相关代码，Next.js 需有有效配置与页面入口；空目录、空文件、单独的 `package.json`、截图或 Agent 返回成功都不算完成。
3. **分类报告**：区分未生成、不完整、正在生成、生成失败、输入已变化和已生成。历史记录不可靠时列为待确认；源码已生成但未导出的项目单列“导出未就绪”，不重新调用 AI。
4. **输出完整清单**：包含 prompt、目标模型真实 ID、期望目录、结论与原因、当前模型可处理性，以及期望总数、已生成数、缺失数和异常数。只检查模式不调用 Agent、不改文件、不登记配置、不写网站。

补生成前必须将实际 Agent 模型 ID 与目标规范 ID 或显式别名匹配。CLI 名称、提供方、服务器名称、端口和相似模型名都不是身份证明；无法核实时只报告并跳过，不能将当前模型结果写入其他模型目录。

默认只补当前模型未生成的组合，已有有效结果直接跳过；不完整、失败、输入变化或待确认项须获明确重试授权。每项启动前再次检查输出并加锁，结束后核验代码及模型归属，登记结果但默认不发布。重试应有上限，失败保留原因，中断后按实际文件和检查点恢复。

即使当前模型的队列已完成，只要其他期望组合仍缺失，整体报告就不能标为完成。例如两个 prompt、两个目标模型应检查四个组合，不能因 out 只出现模型 A 就忽略模型 B。

### 本地模型补全

管理员负责配置并启动 AI 服务器，提供接口地址、API 类型、认证、真实模型 ID 与稳定目录名。批量执行前验证连接、身份及接口能力；不兼容时报告阻塞，不自动换模型。密钥只从本地环境读取，脚本不管理服务器生命周期。

计划接口如下，`model_name` 是项目中的服务配置名称，不是真实模型 ID：

```text
node .\src\workflows\generate-missing.mjs --model <model_name>
```

执行器按上述覆盖规则筛选本轮模型的缺失项。有效代码跳过生成，但仍核对配置登记；登记失败时保留代码，下次仅补登记。已生成但未验证或部署的结果只报告后续阶段，不重复生成。

对允许生成的对象，以目标模型目录为子进程 `cwd`，通过 `child_process.spawn` 等进程 API 非交互调用 `codex exec`，写入范围仅限本次对象。使用 `-c` 配置提供方和 base URL，使用 `--model` 选择实际模型；提示词通过位置参数或标准输入（`codex exec -`）传入，不把 `-c` 当作提示词参数，也不拼接 shell 命令。Windows 下须适配 CLI 包装器或底层可执行入口。

输入包含原始 prompt、`DESIGN.md`、目标目录与验收要求。设置超时和有限重试，收集退出码与错误，核验实际代码后更新状态并登记配置，最终报告生成、登记、跳过、失败及剩余缺失项。

未来 `--check-only` 复用只读覆盖检查；若支持持续轮询，须设置间隔与停止方式。补全脚本不自动部署，网站运行也不依赖本地 AI 服务。

### 增量补部署

计划接口：

```text
node .\src\workflows\deploy-new.mjs
```

管理员选中模型后，检查配置中**所有 `enabled: true` 的结果**，不限于本轮新生成项：

1. 读取对应元数据，核对登记、生成结果与静态导出，未选中的不部署。
2. 检查实际目标的首页、资源和版本一致性；缺失、不完整或旧版本列入待部署，当前版本有效则跳过复制并核对状态。
3. 按静态产物边界准备候选文件，使用共享发布安全机制，同步更新集合入口、详情页和 Carousel；不自动执行 Next.js 构建。
4. 验证通过后设置 `validated`，切换并核验目标成功后设置 `deployed`。目标缺失时纠正过时标记；网站写入成功但状态回写失败时报告，下次先核验目标再补状态，不盲目重复复制。
5. 汇总新增部署、已部署跳过及失败对象，保留已有有效内容与 Git 元数据，支持安全重复运行。

增量补部署不负责取消发布后的旧目录清理；取消选择仍需完整重建。配置登记、选中发布和实际部署是三个独立事实，不能相互代替。
