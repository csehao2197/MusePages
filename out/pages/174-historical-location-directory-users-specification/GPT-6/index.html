03

One person. Their own record.

GET /api/users/me returns the current user's record, never another person's. No user-list or by-ID endpoint exists. Avatar writes require CSRF; the private image response has nosniff, an ETag and private caching, or 404 when absent.

Profile claims refresh from the ID token at every login. Roles remain in the token—not in the application's User record.

Created once.

On first login, the user listener responds to an auth event. A unique realm subject plus read-after-conflict makes simultaneous creation idempotent. Auth does not depend on the user module.

Login comes first.

A failed user write is logged but does not block login. A later login retries; GET /api/users/me can create a missing record on demand. Imported profile claims are optional and limited to feature needs.

Identity outlives an account.

Deleting a Keycloak account currently leaves the User record so location audit references retain meaning. Personal-data cleanup is future feature work—not something this demo performs.

AN EXPLICIT CHOICE

A copy, only when asked.

The intended backend hashes the trimmed, lower-case email with SHA-256, requests a 256px image from the fixed gravatar.com host once, then processes and stores a local PNG copy. Five-second timeout, at most 1 MB, same-host redirects only. The browser never contacts Gravatar.

No email: 409. No image: 404. Provider failure: 502. A saved copy does not follow later provider changes until requested again.

This policy preview will not contact Gravatar or send even the sample email hash.

No third-party request made. In the actual application, fetching would require your explicit request and a CSRF-protected backend action.
