## Implementation

One real Three.js scene: shader grid, lit capsule snake, copper sphere/halo, and optional low rails. The playable 16×16 simulation includes shared-offset gliding, constrained one-slot turn queue, growth, unoccupied random food, five length-based speeds, step-based scoring, wrap/wall/self collision, full-board clear, pause, restart, and change rule. Keyboard, swipe, and four touch keys share the same direction queue. The fixed-south follow camera preserves directional controls.

Web Audio synthesizes the eight-beat loop and interaction tones following Start run. Best scores, ranked initials, and mute persist locally, with storage-denial/corruption resilience. No network backend, API, analytics, mock gameplay, or environment variables. Reduced motion, keyboard focus, dialog focus trapping, hidden-tab pause, adaptive pixel ratio, and a WebGL fallback are implemented.

## Authorized static adaptation

The original requests Vite 6 + TypeScript 5 and a minified `dist` build. This delivery deliberately uses native JavaScript modules and handwritten HTML/CSS under the authorized build-free static adaptation. No Vite/TypeScript build or `dist` is run or claimed. The corresponding modules are `content.js`, `main.js`, `game.js`, `scene.js`, `audio.js`, `ui.js`, plus storage/icons. The locally vendored Three.js distribution is minified; handwritten application modules remain readable. Self-hosted font files and only the three required Lucide icon nodes are included. Scene objects are code-drawn. No external runtime requests are needed. To preserve the complete first-screen line and bead at narrower aspect ratios, the title look target shifts on compact desktops, and the narrow-phone title camera is pulled back 25% along its original sight line; the specified FOV, geometry, coordinates and play camera remain unchanged.

## Limits

Browser-local scores are not shared across devices and can be cleared by browser settings. Audio depends on browser Web Audio support and user activation. A WebGL-capable current browser is required for play; the fallback remains readable without WebGL. Procedural random food is intentionally not an autoplay/pathfinding system. Performance measurements are limited to the installed Chromium test environment; physical-device GPU and audio hardware were not tested.
