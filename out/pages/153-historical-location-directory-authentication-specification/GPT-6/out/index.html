Identity belongs to Keycloak.

Accounts, password changes, role assignments, temporary-password resets and disable/delete actions stay in the provider. No application user-administration endpoints are defined.

Session belongs to the backend.

OIDC authorization code + PKCE. Tokens stay in a server-side in-memory session; the browser receives an HttpOnly, Secure, SameSite=Lax cookie. Thirty minutes idle expiry; restart logs everyone out.

Public means separate.

Only login entry/callback endpoints are public in the application policy. A read-only public map and bearer-token MCP access are distinct post-MVP components.

Source policy question: role-less social users

The general policy says every authenticated user is implicitly a viewer. The later social-login section says a new provider user without roles cannot act until a grant. These statements require reconciliation. This demo shows the stricter pending-role social case separately and does not claim that ambiguity is resolved.

Provider, not automatic linking.

Google is brokered through Keycloak in the source stage environment. An existing email match is denied until the user signs in and explicitly links the provider. Apple is not selected.

Operational exposure stays narrow.

The ingress routes the avarc realm and resources under /auth. Admin, master realm and management port 9000 stay off public ingress. JSON logs exclude login-code query strings; events are held for 30 days.

Recovery preserves identity.

Database backup is primary. User exports preserve IDs, provider links and explicit roles; local passwords need reset after API-only restore. No backup or personal record is accessed in this demo.
